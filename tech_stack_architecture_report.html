Executive Architectural Purpose

ReviewPulse is a production-grade e-commerce intelligence application. It accepts raw, unformatted Amazon.in and Flipkart URLs, autonomously extracts live product specifications, verified customer star ratings, authentic studio photography, and purchaser reviews, and applies an asynchronous multi-stage Natural Language Processing (NLP) pipeline (VADER Sentiment, Aspect-Based Sentiment Analysis, TF-IDF Topic Extraction, Readability Scoring, and N-gram Language Detection) to generate high-fidelity competitive market analytics.

Part 2: "URL say Output ka Safar" (The 10-Step Journey)

An end-to-end breakdown of how a raw Amazon or Flipkart product link is ingested, verified, scraped, analyzed, and visualized on the dashboard.

STEP 1 User Ingestion & Instant Client-Side Pre-Validation
frontend/src/components/shared/UrlAnalyzer.tsx
One-Line: Captures user input, cleans whitespace, and checks URL syntax before network transmission.
The user pastes an e-commerce link (e.g. https://www.flipkart.com/... or https://www.amazon.in/...) into the search bar. The client component checks that the string starts with a valid scheme (or prepends https://), verifies the domain, and starts the animated progress stepper.
STEP 2 URL Normalization & Identifier Extraction (PID / ASIN)
frontend/src/lib/flipkart.ts & amazon.ts
One-Line: Resolves missing parameters and extracts canonical 10-char ASINs or 6-32 char Flipkart PIDs.
If a Flipkart URL uses path routing (/p/itm...) without an explicit query parameter, normalizeFlipkartUrl() extracts the identifier and formats it canonically (?pid=...). Similarly, Amazon URLs are parsed to extract the 10-character alphanumeric ASIN (e.g. B0H2FD3L97).
STEP 3 Asynchronous API Request Dispatch & Observability
frontend/src/lib/api.ts (api.analyzeUrl)
One-Line: Transmits an asynchronous HTTP POST request to the backend with tracking headers and auth.
The client creates an HTTP POST request targeting /api/v1/harvester/analyze-url. It injects a unique X-Request-ID header (e.g. rp-1730740...) for end-to-end tracing and attaches an Authorization: Bearer token.
STEP 4 API Gateway Ingestion, Validation & Market Routing
backend/app/api/v1/harvester.py (analyze_url)
One-Line: Ingests the payload, checks Pydantic schemas, and routes to Amazon or Flipkart scrapers.
FastAPI receives the payload, validates it using AnalyzeUrlRequest, and detects whether the host is Flipkart or Amazon. It checks the database to see if the product has already been analyzed or needs live extraction.
STEP 5 Domain Security Whitelisting & Anti-Phishing Guard
backend/app/services/harvester/flipkart_url.py
One-Line: Rejects insecure HTTP schemes, embedded credentials, and off-domain URLs.
validate_flipkart_url() enforces strict security constraints: requires HTTPS, verifies that the hostname is in ALLOWED_FLIPKART_HOSTNAMES, rejects user/password authority strings, and ensures the PID is alphanumeric.
STEP 6 Live Scraping, Anti-Redirect Shield & Photo Extraction
backend/app/services/harvester/flipkart_live_scraper.py
One-Line: Fetches live HTML, prevents sponsored ad redirects, and extracts 832x832 CDN photos.
The live scraper fetches the product page using desktop browser headers. It executes is_live_page_relevant() to verify that Flipkart hasn't redirected an expired Motorola link to an iPhone sponsored ad. It parses the real selling price, original M.R.P., star rating, customer reviews, and upgrades CDN thumbnails to crisp 832/832 studio photography.
STEP 7 Atomic Database Upsert & Price Snapshot Logging
backend/app/services/harvester/importer.py & price_history.py
One-Line: Persists product details, reviews, and a timestamped price snapshot into PostgreSQL.
The backend creates an atomic database transaction: upserts the Product record with updated prices and image links, creates User and Review records, and logs a new PriceSnapshot row to build the product's historical price trend.
STEP 8 NLP Sentiment, ABSA & Linguistic Computation Pipeline
backend/app/services/sentiment.py & topics.py
One-Line: Analyzes review text to compute sentiment polarity, aspect chips, and topic keywords.
Customer reviews are fed into the NLP engine: VADER polarity scoring categorizes reviews into Positive/Neutral/Negative buckets, Aspect-Based Sentiment Analysis assigns polarity to features (Battery, Display, Camera), and TF-IDF extracts the top n-gram keywords (e.g. "curved display", "battery backup").
STEP 9 Frontend State Merging & Context Synchronization
frontend/src/hooks/useProduct.tsx & Analyze.tsx
One-Line: Merges newly harvested product data into global state and navigates to the workspace.
Upon receiving the 200 OK response, Analyze.tsx calls addProduct(result.product). The ProductProvider unshifts the new product into the active list, sets productId = targetId, and triggers navigation to /products/:id/overview.
STEP 10 Multi-Tab Visual Intelligence Dashboard Rendering
frontend/src/pages/Overview.tsx & ProductWorkspace.tsx
One-Line: Renders the complete, polished product intelligence workspace with charts and quotes.
The Overview screen displays the 100% authentic product image (with referrerPolicy="no-referrer" and studio fallbacks), real selling price, star distribution bars, linguistic customer synthesis ("Customers say..."), aspect badges, and customer quote excerpts.
